# Публичный каталог

Публичная часть платформы: страницы каталога и карточки объекта. Next.js 16,
App Router, серверные компоненты. Клиентского JavaScript нет вовсе — фильтры
работают обычной формой с методом GET.

Кабинет агента здесь пока не живёт: он ждёт провайдера WhatsApp, без которого
номер не подтвердить (см. корневой `README.md`, раздел «Что НЕ сделано»).

## Запуск

Нужна локальная база из корня репозитория:

```bash
./db/rebuild.sh
```

```bash
PGHOST=/tmp PGPORT=55432 PGUSER=postgres psql -q -d partner -f tests/seed.sql
```

```bash
PGHOST=/tmp PGPORT=55432 PGUSER=postgres psql -q -d partner -f db/dev_seed.sql
```

Дальше, из `web/`:

```bash
cp .env.example .env
```

```bash
npm install && npm run dev
```

Проверки:

```bash
npm run typecheck && npm run smoke && npm run build
```

## Как каталог читает базу

Каталог подключается к базе и **понижает права до роли `anon`** — той же,
которой выданы права в `0006_rls.sql`. Это не стилистика, это защита: даже
неправильно написанный запрос здесь физически не достанет ни контактов, ни
комиссии, ни неопубликованного объекта, потому что у роли нет на них прав, а
построчные политики отдают только `publication_state = 'published'`.

Проверка в коде страницы защищала бы только страницу. Проверка в базе защищает
всё, что к базе обращается.

`npm run smoke` проверяет именно это: что права действительно понижены. Если
`set local role` однажды перестанет применяться, запросы пойдут под правами
владельца, и каталог начнёт видеть контакты, ничем себя не выдав.

Транзакция открывается как `read only`, поэтому каталог не может записать ничего
даже случайно.

## Что где лежит

```
app/
  layout.tsx            шапка, подвал, метаданные
  page.tsx              каталог: фильтры, сетка, страницы
  object/[id]/page.tsx  карточка объекта и похожие предложения
  report/[token]/page.tsx  отчёт собственнику по личной ссылке
  components.tsx         карточка объекта в сетке
  not-found.tsx         объекта нет в каталоге
  sitemap.ts            карта сайта из той же витрины
  robots.ts             robots.txt
lib/
  db.ts                 пул соединений и понижение прав
  catalog.ts            запросы к public_catalog_v
  report.ts             отчёт собственнику одним документом из базы
  format.ts             цены, площади, склонения, свежесть
  types.ts              строка витрины и фильтры
scripts/
  smoke.mjs             проверка понижения прав
```

## Решения, которые стоит знать

**Фильтры живут в адресе страницы.** Обычная форма с `method="get"`, никакого
клиентского состояния. Поэтому ссылку на выборку можно отправить в мессенджере,
а поисковик её проиндексирует. Клиентского кода для этого не нужно вовсе.

**Свежесть подтверждения показывается покупателю.** Инвариант 5 держит
`actual_at`: агент подтверждает, что цена и фотографии ещё в силе. Каталог
показывает это прямо на карточке — «подтверждено вчера» или «не подтверждалось
21 день», и сортировка по умолчанию идёт по свежести, а не по дате публикации.
Без этого инвариант остался бы внутренней деталью, невидимой тому, для кого он
и сделан. Ни у одной из пятнадцати изученных систем такого в публичной части
нет.

**Похожие предложения не требуют совпадения района.** Свой район идёт первым,
но не обязателен: в Бишкеке в одном районе и в одной цене редко оказывается
больше одного предложения, и строгий фильтр давал бы пустой блок почти всегда.

**Контакты собственника в каталог не выносятся.** Это инвариант 4, и он держится
политиками базы, а не решением страницы: витрина `public_catalog_v` контактов не
содержит, а роль `anon` не имеет прав на `contacts` и `contact_phones`.

## Отчёт собственнику

`/report/<токен>` — страница по личной ссылке, без входа: у собственника нет
аккаунта и не должно быть. Вся защита в базе: токен проверяется функцией
`app.owner_report()`, она же решает, что показать. Страница получает готовый
документ и не ходит по таблицам, поэтому показать лишнее ей нечем.

Страница закрыта от индексации дважды: `noindex` в метаданных и `Disallow` в
`robots.txt`. Первое — запрет, второе — просьба, и порядок именно такой.

Транзакция для отчёта пишущая, в отличие от каталога: функция считает
просмотры, и агенту это говорит, дошла ли ссылка, а не только отправлена ли
она.

## Чего нет

- **Фотографий.** Колонка `photos` в витрине есть, хранилища нет, в данных для
  разработки фотографий нет. Карточки пока текстовые.
- **Карты.** Поиск по области на карте есть почти у всех конкурентов; у нас в
  объекте пока нет координат, только адрес и зона.
- **Киргизского языка.** Интерфейс только на русском.
- **Пагинации по курсору.** `limit/offset` на восемнадцати объектах не проблема,
  на десятках тысяч станет.
